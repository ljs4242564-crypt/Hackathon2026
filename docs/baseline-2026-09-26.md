- 루트: HTTP 200, `text/html; charset=UTF-8`

- 응답 본문: `Site Unavailable`이 아니라 SCNU Campus Assistant HTML/Health JSON
- 보안 헤더: CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, Referrer Policy 확인

따라서 구현 지시서에 적힌 과거의 `HTTP 200 + Site Unavailable` 상태는 현재 재현되지 않았다. 다만 배포 플랫폼 또는 공식 사이트의 일시 장애에 대비한 fallback은 여전히 필요하다.

## 확인된 구조와 문제

- Hono + React + Vite + Cloudflare Pages 구조로, 현재 플랫폼 기본 배포 방식과 호환된다.
- 규칙 기반 분석, 공식 도메인 Allowlist, redirect 재검증, SSRF 방어가 이미 구현되어 있다.
- `chatRoute`가 검색과 원문 Fetch를 직접 순차 호출하여 전체 실시간 조회 제한과 fallback 경계가 없다.
- `pageFetcher.ts`의 학사일정 예외가 빈 `catch`에서 사라져 실패 원인을 상태와 로그에 반영하지 못한다.
- 검색/원문 조회 실패와 정상 조회 결과 없음이 최종적으로 모두 `not_found`가 될 수 있다.
- 정적 또는 영구 스냅샷 저장소가 없다.
- API 상태는 `verified`, `conflicting`, `not_found`만 제공하며 live/snapshot/stale/unavailable 구분이 없다.
- 기본 테스트의 `chatRoute` 정상 질문 테스트가 실제 도서관 사이트에 접근한다. 이번 점검에서는 통과했지만 외부 네트워크 상태에 따라 불안정할 수 있다.
- README 배포 상태는 현재 확인 결과와 일치하지만, 확인 시각과 장애 판정 기준이 기록되어 있지 않다.

## 알려진 제한

- HTML과 학사일정 JSON 이외의 PDF, HWP/HWPX, 이미지 기반 공지는 자동 추출하지 못한다.
- 동적 도서관 페이지의 일부 정보는 서버 Fetch만으로 확인하기 어렵다.
